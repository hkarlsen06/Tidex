# Scaffolding Examples & Patterns

## Real Examples from the Codebase

### Example 1: Button Component (Two-Tier Pattern)

**Base Component** (`components/ui/button.tsx`):
- Generated by shadcn/ui
- Uses class-variance-authority for variants
- Generic, reusable component
- **Never imported directly in app code**

**App Wrapper** (`components/app/Button.tsx`):
- Imports base component as `BaseButton`
- Adds app-specific props (e.g., `loading`)
- Adds app-specific styling
- **This is what gets imported throughout the app**

```typescript
// ✅ Correct
import { Button } from '@appui/Button';

// ❌ Wrong - never do this
import { Button } from '@ui/button';
```

### Example 2: Settings Page (Pay Settings)

**Structure:**
```
app/(app)/settings/pay/
  └── page.tsx                          # Server component, loads data
components/settings/pay/
  ├── PayForm.tsx                       # Client component, form logic
  └── SupplementRulesEditor.tsx         # Sub-component
```

**Data Flow:**
1. Page component: Fetch user + settings server-side
2. Page component: Pass data to form component
3. Form component: Handle user input client-side
4. Form component: POST to API route
5. API route: Update database
6. Form component: Call `router.refresh()` to update

### Example 3: Shifts Route (Full Feature)

**Structure:**
```
app/(app)/shifts/
  ├── page.tsx                          # Entry point
  ├── _data/
  │   └── getShifts.ts                  # Data loader (server-only)
  └── _components/
      ├── ShiftCalendar.tsx             # Calendar view
      ├── ShiftList.tsx                 # List view
      └── AddShiftDialog.tsx            # Add shift modal
components/shifts/
  ├── ShiftCard.tsx                     # Individual shift card
  └── ShiftStats.tsx                    # Statistics display
lib/payroll/
  └── calc.ts                           # Pure calculation logic
```

**Key Pattern:**
- Data loader (`_data/getShifts.ts`) fetches raw data + computes wages
- Page receives enriched data, passes to view components
- View components are "dumb" - just render props
- No client-side wage calculation (server-computed only)

## Common Scaffolding Scenarios

### Scenario 1: Adding a New shadcn Component

**Steps:**
1. Run: `npm dlx shadcn@latest add [component-name]`
2. Creates `components/ui/[component-name].tsx`
3. **Don't stop here!** Create app wrapper:

```typescript
// components/app/[ComponentName].tsx
import * as React from "react";
import { [ComponentName] as Base[ComponentName] } from "@ui/[component-name]";
import { cn } from "@/lib/cn";

type Props = React.ComponentProps<typeof Base[ComponentName]>;

export function [ComponentName]({ className, ...props }: Props) {
  return (
    <Base[ComponentName]
      {...props}
      className={cn(
        // Add semantic tokens if needed
        className
      )}
    />
  );
}
```

4. Export from `components/app/index.ts` (if exists)
5. Import in your code: `import { [ComponentName] } from '@appui/[ComponentName]'`

### Scenario 2: Adding a New Settings Page

**What to generate:**

1. **Route file** (`app/(app)/settings/[page-name]/page.tsx`):
   - Server component
   - Auth check
   - Load user settings via `getUserSettings()`
   - Render form component

2. **Form component** (`components/settings/[page-name]/[PageName]Form.tsx`):
   - 'use client' directive
   - Form state management
   - Submit handler (POST to API)
   - Loading states
   - Uses semantic tokens

3. **API route** (if new settings fields):
   - `app/api/settings/[endpoint]/route.ts`
   - Auth check
   - Validate input
   - Update `user_settings` table
   - Return JSON response

4. **Update types** (if new fields):
   - Add to `UserSettings` type in `lib/payroll/types.ts`

**Example command:**
> "Scaffold a notifications settings page with email/push toggle fields"

### Scenario 3: Adding a New Authenticated Route

**What to generate:**

1. **Route directory** (`app/(app)/[route-name]/`)
2. **Page component** (`page.tsx`):
   - Server component
   - Auth check via `createSupabaseServerClient()`
   - Call data loader
   - Pass data to view component

3. **Data loader** (`_data/get[DataName].ts`):
   - `import "server-only"` at top
   - Async function that fetches from Supabase
   - Processes/enriches data if needed
   - Returns typed data

4. **View component** (`components/[route-name]/[RouteName]View.tsx`):
   - Client component ('use client')
   - Receives data as props
   - Renders UI with semantic tokens

**Example command:**
> "Scaffold a reports route with monthly/yearly filters and export button"

### Scenario 4: Adding a Complete Feature

**What to generate:**

1. **Database migration** (manual, but can scaffold template):
   ```sql
   -- supabase/migrations/[timestamp]_add_[feature].sql
   CREATE TABLE public.[table_name] (
     id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
     user_id UUID REFERENCES auth.users(id) ON DELETE CASCADE,
     created_at TIMESTAMPTZ DEFAULT NOW(),
     -- feature-specific fields
   );

   -- RLS policies
   ALTER TABLE public.[table_name] ENABLE ROW LEVEL SECURITY;

   CREATE POLICY "Users can view own [feature]"
     ON public.[table_name]
     FOR SELECT
     USING (auth.uid() = user_id);

   CREATE POLICY "Users can insert own [feature]"
     ON public.[table_name]
     FOR INSERT
     WITH CHECK (auth.uid() = user_id);
   ```

2. **Types** (`lib/types/[feature].ts`):
   - Database row type
   - Enriched/computed type
   - Input/form type
   - API response type

3. **Route** (`app/(app)/[feature]/page.tsx`)
4. **Data loader** (`app/(app)/[feature]/_data/get[Feature].ts`)
5. **View component** (`components/[feature]/[Feature]View.tsx`)
6. **API routes** (`app/api/[feature]/route.ts` for CRUD operations)
7. **Sub-components** as needed

**Example command:**
> "Build a shift templates feature where users can save/load common shift patterns"

## Anti-Patterns to Avoid

### ❌ Don't: Import from components/ui directly
```typescript
// Wrong
import { Button } from '@ui/button';
```

### ✅ Do: Import from components/app
```typescript
// Correct
import { Button } from '@appui/Button';
```

---

### ❌ Don't: Use hardcoded Tailwind colors
```typescript
// Wrong
<div className="bg-slate-900 text-gray-400">
```

### ✅ Do: Use semantic color tokens
```typescript
// Correct
<div className="bg-surface-primary text-text-secondary">
```

---

### ❌ Don't: Instantiate Supabase clients directly
```typescript
// Wrong
import { createClient } from '@supabase/supabase-js';
const supabase = createClient(url, key);
```

### ✅ Do: Use helper functions
```typescript
// Correct - Server Component
import { createSupabaseServerClient } from '@/lib/supabase/server';
const supabase = await createSupabaseServerClient();

// Correct - Client Component
import { supabase } from '@/lib/supabase/browser';
```

---

### ❌ Don't: Compute wages client-side
```typescript
// Wrong
'use client';
export function ShiftCard({ shift }) {
  const gross = calculateGross(shift); // ❌ Don't calculate on client
}
```

### ✅ Do: Pass precomputed data from server
```typescript
// Correct - Server Component
export default async function ShiftsPage() {
  const { shifts } = await getComputedShifts(userId); // ✅ Computed server-side
  return <ShiftCard shift={shifts[0]} />;
}

// Client Component just displays
'use client';
export function ShiftCard({ shift }) {
  return <div>{shift.computed.gross}</div>; // ✅ Just render
}
```

---

### ❌ Don't: Fetch data in client components
```typescript
// Wrong
'use client';
export function MyComponent() {
  const [data, setData] = useState([]);
  useEffect(() => {
    fetch('/api/data').then(r => r.json()).then(setData); // ❌ Client fetch
  }, []);
}
```

### ✅ Do: Fetch in server components or data loaders
```typescript
// Correct - Server Component
export default async function MyPage() {
  const data = await getData(userId); // ✅ Server fetch
  return <MyView data={data} />;
}
```

## Checklist for Scaffolded Code

When generating code, ensure:

- [ ] All server imports use `await createSupabaseServerClient()`
- [ ] All client imports use shared `supabase` instance
- [ ] No imports from `components/ui` (only from `components/app`)
- [ ] All colors use semantic tokens (bg-surface-*, text-text-*, etc.)
- [ ] Server-only code has `import "server-only"` at top
- [ ] Client components have `'use client'` directive
- [ ] Data loaders are in `_data/` folders
- [ ] TypeScript types are exported and imported
- [ ] Auth checks before any data fetching in protected routes
- [ ] Error handling with try/catch and logger
- [ ] Loading states for async operations
- [ ] Form submissions call `router.refresh()` after success

## Naming Conventions Summary

| Item | Convention | Example |
|------|------------|---------|
| Component files | PascalCase.tsx | `Button.tsx`, `ShiftCard.tsx` |
| Component names | PascalCase | `Button`, `ShiftCard` |
| Data loaders | get[Name].ts | `getShifts.ts`, `getUserSettings.ts` |
| Function names | camelCase | `getShifts()`, `computeGross()` |
| Type names | PascalCase | `ShiftRow`, `UserSettings` |
| Variables | camelCase | `totalHours`, `shiftDate` |
| Constants | UPPER_SNAKE_CASE | `PRESET_SUPPLEMENT_RULES` |
| Database tables | snake_case | `user_shifts`, `user_settings` |

## Common Feature Requests & How to Scaffold

### "Add a new chart to the stats page"
**Generate:**
- New chart component in `components/stats/[ChartName]Chart.tsx`
- Update stats data loader to include chart data
- Add chart to stats page

### "Add a new field to user settings"
**Generate:**
- Update `UserSettings` type
- Add field to settings form component
- Update API route to handle new field
- Migration file template (manual execution)

### "Create a new dashboard widget"
**Generate:**
- Widget component in `components/dashboard/[Widget]Widget.tsx`
- Add to dashboard page
- Data loader if widget needs specific data

### "Add export to Excel"
**Generate:**
- API route in `app/api/export/excel/route.ts`
- Button in data settings page
- Server-side Excel generation logic

### "Add recurring shift patterns"
**Generate:**
- New route `app/(app)/templates/`
- Template CRUD components
- Database table migration template
- API routes for template management
