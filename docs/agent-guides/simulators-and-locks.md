# Devices and simulators

Read this guide before running tests on physical phones, acquiring a shared simulator, or driving a simulator by hand.

### Devices and simulators

Agents in several repos share this Mac, and simulators created by agents once filled its disk. Whenever the app or tests run:

- Run `./scripts/xcode-test-agent.sh --devices` or `ios-agent devices --json` to discover physical phones and their eligibility. Only audited device-safe test selections automatically prefer the approved spare phone. Full test suites and other selections use the shared simulator. Other connected phones require explicit authorization. Keep simulator fixtures and UI journeys on a simulator; preserve physical app data.
- Automatic phone runs require explicit `-only-testing:<Target>/<Suite>` selections from `ISO8601TimestampTests` and `AppDeepLinkResolverTests`. Other suites can purge shared app storage and stay on simulators.
- Leave `XCODE_TEST_AGENT_DESTINATION` unset for automatic selection. Set an explicit simulator destination for simulator-only fixtures. Discovery failure or an unavailable spare falls back to the shared simulator.
- Take a simulator through `scripts/lock` and use the one it names. `Shared iPhone` stays booted. `Shared iPhone 2` and `Shared iPhone 3` boot only while the ones before them are busy. Each stays booted for five minutes after its release, so the next agent skips the boot, and shuts down at once when macOS reports critical memory pressure. The user can make the pool smaller with `IOS_AGENT_SIMULATORS=1` or `2`. To clear simulator app data, uninstall it instead of erasing the simulator.
- Small-screen or screenshot workflows that require a simulator outside the shared pool need an explicitly authorized temporary machine-policy exception. Shut that simulator down and restore the default policy afterward.
- Before every run on a simulator, the wrapper uninstalls Tidex there, on a shared simulator while it holds that simulator's lock. If a run fails with "test runner hung before establishing connection" or "failed to launch no.tidex.app", run it again through the wrapper.
- Before you drive a simulator by hand, take one with `SIM="$(scripts/lock acquire simulator)"`. It prints the name of a free shared simulator, boots it if needed, and waits while the enabled slots are busy. Start every simulator command with `SIM="$(scripts/lock acquire simulator)" &&` and use `"$SIM"` in it. While your worktree holds a simulator, the command returns that same one and counts as a use. A session nobody has used for 10 minutes goes stale, so a simulator you forget to release frees itself 10 minutes after your last command. Agents get a simulator in the order they asked. A session older than 15 minutes gives the simulator to the agents waiting for it at its next command, and waits in line to get it back. `scripts/lock` says so on stderr. Reinstall your app and open your Device panel session again then, because another worktree has used the simulator. A waiting `scripts/lock` that a tool timeout stops keeps its place in line for 15 minutes, so run the same command again. When you're done, close your T3 Device panel session with `device_close` first, then release the simulator with `scripts/lock release simulator`. T3 keeps its own session on the simulator, and no other agent can open it in the Device panel until you close yours. Driving by hand covers the T3 Device panel (`device_open`), `agent-device`, `xcrun simctl install`, `launch` and `uninstall`, sign-in scripts and end-to-end play. The locks are machine-wide, so Paeonia agents share the same simulator locks. `scripts/lock status` shows who holds each one. Never close or take over the device session of an agent that holds the simulator's lock. Once you hold the lock, a session another agent left open on that simulator is yours to close.
- On a physical device, the wrapper uninstalls nothing. If a run there fails that way, ask the user before uninstalling, because that deletes the app's data on the device.
- Do not download simulator runtimes or platforms, through `xcodebuild -downloadPlatform`, `xcrun simctl runtime add` or Xcode's Components settings. If a shared simulator is missing or no runtime is installed, report that in the handoff and finish the rest of the task.
- `./scripts/xcode-build-agent.sh` builds for the generic simulator destination. That needs no simulator or runtime, so these rules don't change it.
